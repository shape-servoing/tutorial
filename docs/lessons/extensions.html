In the tutorial

The loop extends without changing its structure. Two additions each add one term to the control law \vu=\alpha\,\vJh^{+}\ve, and they can be used separately or together.

Time-varying targets. For a target \vs^{*}(t), the shape error changes even when the robot does not move, \dot{\ve}=\dot{\vs}^{*}-\vJ\vu, so feedback alone lags behind the target; a larger gain \alpha reduces the lag but does not remove it. A feedforward term compensates for the target motion:

\vu_k=\alpha\,\vJh_k^{+}\ve_k+\vJh_k^{+}\dot{\vs}^{*}_k,

where \dot{\vs}^{*}_k is the target velocity at iteration k.

Secondary tasks. When the shape-servoing task leaves some robot motion directions unconstrained, that is, when \Null(\vJh_k) is nontrivial, a secondary task can request a robot velocity \vu_{2,k}, whose projection onto this null space is added to the command:

\vu_k=\alpha\,\vJh_k^{+}\ve_k+\big(\mathbf{I}_m-\vJh_k^{+}\vJh_k\big)\,\vu_{2,k},

where \mathbf{I}_m is the m\times m identity matrix. According to the estimate, the projected motion leaves the features unchanged to first order. Here, the secondary task drives the left gripper toward a marker (m_x,m_y) with \vu_{2,k}=\beta\,[\ve_{\mathrm{m},k}^{\top},0,0,0,0]^{\top}, where \ve_{\mathrm{m},k}=[m_x-x_{L,k},\,m_y-y_{L,k}]^{\top} is the marker error of the left gripper.

Two feature representations. The secondary task can itself be a feature task. With curvature-based features as the primary features and \vu_{2,k}=\beta\,\vJh_{\mathrm{p},k}^{+}\ve_{\mathrm{p},k}, where \ve_{\mathrm{p},k} and \vJh_{\mathrm{p},k} are the error and Jacobian estimate of the point coordinates, the curvature-based features unloop a looped rod with little stretching while the projected point-coordinate task moves it to the target pose. Only \vJh_{\mathrm{p},k} is estimated: the turning angles \boldsymbol{\kappa} are a known function of the point coordinates \vs_{\mathrm{p}}, so the chain rule gives \vJh_k=(\partial\boldsymbol{\kappa}/\partial\vs_{\mathrm{p}})\,\vJh_{\mathrm{p},k}, and robot motions that \vJh_{\mathrm{p},k} predicts to move the tracked points rigidly lie in \Null(\vJh_k).

The same loop also applies to three-dimensional objects (Demo 12). Plastic and other history-dependent materials require a different extension, because the relation between \vq and \vs then depends on the manipulation history.

Try this

  1. Moving target: run with the feedforward term on, then off. Without it, the rod lags behind the swaying target; with it, the tracking error stays small.
  2. Without feedforward, raise \alpha: the lag shrinks but does not vanish.
  3. Secondary task: the features are curvature-based (n=3<m=6), and the shape is held at its current value. Drag the marker: the left gripper follows it while the rod keeps its shape.
  4. Switch the projection off: the same secondary command now also deforms the rod, and the shape error rises while the first term of the control law corrects it.
  5. Shape and transport: run with transport on. The curvature-based features open the loop, and the point-coordinate task carries the rod to the target pose without stretching it. Reset and run with transport off: the rod reaches the target shape but stays where it started.

The feedforward term compensates for the motion of a time-varying target, and the null space of the estimate allows secondary tasks that, to first order, leave the regulated features unchanged.

What this demo computes

The moving target is the equilibrium of the rod at a grasp that sways and tilts with a period of 120 iterations, and \dot{\vs}^{*}_k is the target change over the next control period \Delta t=1. The secondary task of the second tab uses \beta=0.05; the point-coordinate task of the third tab uses \beta=0.1, with the damped inverse. There, \vJh_{\mathrm{p},k} starts from an offline regression around the looped rod and is updated with Broyden's rule at every iteration, with transport on or off.
