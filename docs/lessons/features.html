In the tutorial

The shape features define how the measured object is represented for feedback control. A different representation changes only the feature map f in the perception block, but because the error \ve=\vs^{*}-\vs is defined in feature space, it determines which geometric quantities are regulated. Section VI of the tutorial compares three representations built from the same tracked points \vp_1,\dots,\vp_P:

  • point coordinates \vs=[\vp_1^{\top},\dots,\vp_P^{\top}]^{\top}\in\R^{2P}, which retain both the shape and the pose of the object (extrinsic features) and change with any rigid translation or rotation;
  • edge vectors \vd_i=\vp_{i+1}-\vp_i, invariant to translation but not to rotation;
  • curvature-based features, for which the discrete curvature is measured through the turning angles \kappa_i, the signed angles between \vd_i and \vd_{i+1}; they describe local bending and are invariant to both (intrinsic features).

A controller can regulate only the differences that its feature vector represents: any robot velocity that moves the object only in ways to which the features are invariant lies in \Null(\vJ). For curvature-based features, n=P-2=3<m=6, so at least three robot directions lie in this null space, among them the gripper motions that translate or rotate the rod rigidly.

In the running example, a temporary disturbance, of the kind a real setup can introduce, pulls the grippers during the first 20 iterations and tends to move the rod rigidly away from the target pose. Point coordinates register this drift as an error, so the loop resists it and, once the disturbance stops, returns the rod to the target pose. Edge vectors ignore translations, and curvature-based features also ignore rotations, so the loop leaves that part of the drift uncorrected: the rod reaches the target shape shifted, or shifted and rotated.

Feature choice also affects the path that the object follows toward the target. Edge vectors and curvature-based features encode the material connectivity of the object, so their errors reflect quantities related to local stretching and bending, whereas the point-coordinate error measures image distances between points regardless of how they are connected through the material. In the Looped rod tab, the rod starts as a hanging ring, and all three representations reach the same unlooped target. With point coordinates, the loop tightens near the grippers, and the largest axial strain reaches about 27%; with curvature-based features, the loop opens first, and the strain never exceeds its initial 2.1%; with edge vectors, it peaks at about 3%. The outcome depends on the initial and target shapes.

Try this

  1. In Invariances, press Translate: only the point coordinates change, and all their x components (and all y components) coincide.
  2. Press Rotate: point coordinates and edge vectors change, while the curvature does not.
  3. Press Bend: all three representations change.
  4. In Closed loop, run each representation, or press Compare all three. During the first 20 iterations the disturbance pulls the rod to the right; with point coordinates the loop brings it back to the target pose, with edge vectors the rod reaches the target shape shifted, and with curvature-based features shifted and rotated.
  5. Run a Null-space motion for edge vectors or curvature-based features: the robot and the rod move, but the features do not change.
  6. In Looped rod, run point coordinates and watch the strain plot while the grippers pull the loop tight; then run curvature-based features, or press Compare all three.

The feature representation is part of the task definition, not only a measurement choice. Retain position information when the object must reach a shape at a particular pose, and remove rigid motion from the error when only the intrinsic shape matters or when the object should be deformed as little as possible on the way. Both can be combined: Demo 11 regulates curvature-based features and moves the rod to its target pose with a point-coordinate secondary task in the null space.
